Pipelined Rendering

Render a scene one frame behind its simulation to overlap rendering with the next frame’s work.

By default a frame runs every world in sequence: the scene simulates, extracts its renderable state, renders, and only then can the window’s UI and the next frame start. With pipelined rendering, the scene’s render world draws frame N while the simulation and UI already prepare frame N+1. Extraction is the only point where the two meet: before extracting frame N+1, the engine waits for frame N to finish.

A frame then takes about as long as the slower of the two paths instead of their sum. The cost is one frame of input latency, about 7 ms on a 143 Hz display. Pipelining does not reduce GPU time: when the GPU is already the limit, the frame rate does not change.
