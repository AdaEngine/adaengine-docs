Authoring skeletal animation

Copy an imported animation or capture a rest/current pose into a project-owned .animlib resource. Source GLB/glTF bytes remain unchanged. Swift code, Studio’s Animator, the editor agent and project Tools share the same data and edit commands.

Opening a GLB/glTF or .animlib in Studio reveals the bottom . A resizable panel shows the imported node hierarchy, and the right Inspector follows bone, track, key and graph selection. The timeline places all bones on a shared seconds ruler with a draggable playhead, clip/duration/loop controls, key insertion and grouped editing. Graph uses connected pose cards on a canvas. These surfaces share the large center viewport’s player and camera. Asset editing does not require an open scene. See the Studio animation-authoring guide for the complete pointer and keyboard workflow.

A binding snapshots the complete hierarchy: stable node IDs, parents, names, rest matrices/TRS and morph target widths. Tracks target hierarchy nodes, including non-joint nodes, rather than offsets in a skin palette. Changed rigs fail binding explicitly; guessing by duplicate bone names or reordered indices is not remapping.
